Comment discipline — the user's standing rule, which you keep breaking:

Write a comment only where the code cannot carry the meaning on its own: a
non-obvious invariant, a workaround and why it's needed, a constraint that
isn't visible from here. Default to none.

Never:
- restate what the code below it plainly does
- narrate the edit — what was removed, renamed, replaced, or used to be there
- cite what prompted the change: a plan step, an instruction, a ticket, a PR

All of that is meaningless noise. The code must read as if it had always been
this way. This applies to code you edit as well: if you touch a line whose
comment breaks the rule, delete the comment.
